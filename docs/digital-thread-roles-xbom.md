# 数字线索 · 角色体系与 XBOM 关系（面向型号总师与工业软件方案）

## 1. 定位与前提
- 数字线索将“结构化对象”作为主语，XBOM 是跨域语义骨架（Single Structure of Truth），统一承载层级路径、配置状态、版本/基线与跨域关联。
- 设计（Design）、仿真（Simulation）、试验（Test）三大域围绕 XBOM 节点聚合数据与结论，所有度量与决策都可回溯到“哪个结构、哪一版、在什么边界条件下”。

## 2. 主要使用角色
- 总师 / 系统工程师（SE）：定义研制目标与收敛策略，关注覆盖率、成熟度、风险闭环，需要总览与下钻。
- 分系统主任设计师（结构/热/控制等）：关注“本系统 需求→设计→仿真→试验”的一致性与变更影响。
- 仿真工程师：沿结构路径管理实例/版本/工况，校核模型可信度，输出可复用证据与适用边界。
- 试验工程师：按“结构→试验类型→项目/运行”组织，管理样机/工装/仪器配置与实测结论。
- 配置/质量工程（CM/QE）：基线、变更、质量门的治理与发布控制。
- 工艺制造与装配（ME）：基于 XBOM 校验可制造/装配性，跟踪实物 BOM 与设计/试验一致性。
- 项目管理（PMO）：进度、风险、资源与里程碑的跨域汇总（结构层级度量）。
- 数据治理/平台：维护映射规则与数据契约，确保跨系统一致性与审计能力。

## 3. 角色 — XBOM 读/写关注点
- 总师/SE：读覆盖、成熟度、风险、差异热区；写“评审结论/处置建议（受控）”。
- 分系统主任：读系统路径指标/变更影响；写结构标注、需求对齐状态、变更申请（经 CM 流程）。
- 仿真工程师：读结构路径与基线；写“实例/版本→结构”的映射、有效性标签、结果摘要与适用边界。
- 试验工程师：读结构与试验类型映射、样机配置；写“项目/运行→结构”的挂接、条件/样机/仪器配置与合格性结论。
- CM/QE：读全局；写“基线/变更单/质量门结果”，控制可发布与冻结。
- ME：读结构状态；写“可制造/装配性评审结论、工艺约束”并绑定结构。
- PMO：读结构层级态与里程碑；写进度与风险条目（不改结构本体）。

## 4. XBOM 映射与数据契约（关键字段）
- 主键与路径：`xbomNodeId` + `structurePath[]` + `baselineId`。
- 版本/配置：`configState`（设计/试验/仿真）、`changeId`（ECO/MRB 等）。
- 试验映射：`structurePath[]` + `testTypeCode` → `projectId/runId`（一对多）；保存样机/工装/仪器配置哈希，支持可重复性。
- 仿真映射：`structurePath[]` + `simTypeCode` → `instanceId/version`（一对多）；保存边界条件集合与有效性标签。
- 证据与结论：统一“证据”接口（附件/曲线/表格）与“结论”接口（通过/条件通过/不通过；适用范围、限制与假设）。

## 5. 面向总师的闭环流程（围绕 XBOM 展开）
- 需求对齐：需求→结构映射完成度与差异热区。
- 设计成熟度：基线状态、变更影响面（受影响结构子树）；证据对齐度。
- 验证证据：按结构聚合“仿真可信度 × 试验证据”矩阵，分层展现（系统/分系统/部件）。
- 风险收敛：结构级风险库（FMEA/FTA）× 证据联动，形成“剩余风险 × 复用建议”。

## 6. 度量体系（结构层级汇总）
- 覆盖率：需求→结构映射率、仿真覆盖（场景×边界）、试验覆盖（类型×项目）。
- 成熟度：TRL/VRL（由证据权重与质量门结果汇总）。
- 一致性：设计/仿真/试验 参数与边界一致性指数、差异热区排行。
- 效率：变更闭环 Lead Time、证据复用率、失效率/退回率。

## 7. 权限与治理
- XBOM 本体写权：SE/主任/CM 受控；其余角色通过“挂接/映射/结论”接口写从属数据。
- 证据发布：仿真/试验证据进入“待审”，经质量门通过后挂入结构基线。
- 变更管理：影响结构语义或证据有效性的变更必须绑定 `changeId` 并触发影响分析。

## 8. 系统交互建议（与现有模块对齐）
- 模块首页：面向总师的“理念→映射→角色路径”信息架构，并提供一键进入“仿真导航/试验结构/设计结构/方案概览”的快捷卡片。
- XBOM 视图（原“需求详情”已统一命名为“XBOM”）：左侧结构树 + 右侧证据/差异/变更/风险分区；总览与下钻一致。
- 角色化入口：角色卡片预设筛选与默认标签页（仿真工程师→仿真导航；试验工程师→试验结构），减少跨层跳转。
- 证据统一抽屉：在任一结构节点统一查看“仿真实例版本/试验运行/设计输出/质量门”。

## 9. 落地要点
- 以 XBOM 为唯一结构主键，禁止“域内自造结构”；所有数据均挂接回 XBOM。
- 清晰分离“结构写权”与“证据/结论写权”，审计链可追溯。
- 首先上线“指标面板 + 角色快捷入口 + 证据统一抽屉”，后续迭代“变更影响分析与质量门自动化”。
