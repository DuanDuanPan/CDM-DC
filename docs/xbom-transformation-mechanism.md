# XBOM 转化机制说明（含原理对象映射）

## 1. 背景与目标
- 构建从需求到试验的跨阶段数字主线，确保每一次决策、验证与变更都可追溯。
- 以 XBOM（跨域 BOM）为语义骨架，在 RBOM→ABOM→DBOM→CAEBOM/TBOM 的阶段内提供稳定的节点标识与关联关系。
- 引入“原理对象”作为贯穿各 BOM 的抽象锚点，实现“需求语义→系统方案→详细设计→仿真/试验证据”的一致性。

## 2. XBOM 阶段定义
### RBOM（需求 BOM）
- 由需求工程产生，围绕系统、子系统、部组件的“功能/性能/结构/架构”约束组织。
- 典型字段：需求编号、层级路径、约束条件、验收准则、原理对象引用。

### ABOM（系统/方案 BOM）
- 由系统设计/分析工具输出的候选方案结构，强调“功能/逻辑/初步物理”三层模型。
- 典型字段：方案编号、功能/逻辑/物理模型链接、参数集、评审状态、原理对象引用。

### DBOM（设计 BOM）
- 方案评审后锁定的详细设计结构，包含可交付的物理件、文件、参数、质量特性。
- 典型字段：零部件编号、3D/MBD/图纸链接、材料、接口信息、原理对象引用。

### CAEBOM（仿真 BOM）
- 以 DBOM 为骨架，挂接结构/热等仿真实例，组织维度为“仿真类型→实例→版本”。
- 典型字段：仿真类型代码、实例/版本、边界条件、可信度标签、原理对象引用。

### TBOM（试验 BOM）
- 同样以 DBOM 为骨架，挂接试验类型、项目、任务与样机配置。
- 典型字段：试验类型代码、项目/任务、样机/工装配置、结论状态、原理对象引用。

## 3. 原理对象贯穿策略
### 3.1 定义与定位
- 原理对象（Principle Object）描述“实现某项功能或满足某种约束的工程原理抽象”，位于功能语义与物理实现之间。
- 粒度遵循：一个原理对象只覆盖单一功能/关键设计准则，能够映射到一个或多个实现节点。

### 3.2 核心字段
| 字段 | 说明 |
| --- | --- |
| `principleId` | 全局唯一编号，支持版本化（如 `PO-ENG-001@v3`）。 |
| `name` | 规范命名，反映工程语义，如“同轴涡轮泵-双级增压原理”。 |
| `purpose` | 目标功能/性能描述。 |
| `applicability` | 适用条件、边界、假设。 |
| `interfaces` | 关键接口/约束（压力、转速、连接方式等）。 |
| `evidenceRefs` | 已验证的仿真/试验证据引用。 |
| `status` | 候选/选定/废弃，用于方案筛选后的残留管理。 |

### 3.3 映射关系
- RBOM 需求项必须绑定至少一个原理对象，用于解释需求背后的工程实现思路。
- ABOM 节点在方案对比时引用原理对象，以说明方案选择依据；未被选中的节点状态标注为“候选”。
- DBOM 零部件记录原理对象，体现具体实现对原理的继承；必要时可多个零部件共用同一原理对象。
- CAEBOM/TBOM 的仿真/试验实例通过结构节点继承原理对象 ID，确保验证证据与原理一一对应。

### 3.4 维护流程
1. 新增结构节点时，必须选择现有原理对象或提交新建审批，系统执行空白映射校验。
2. 原理对象变更触发影响分析，列出关联的需求、方案、设计件、仿真/试验任务。
3. 废弃原理对象需提供替代映射，防止 RBOM 或下游节点悬挂。

## 4. 转化流程概览
### 4.1 RBOM → ABOM
- 输入：需求层级树（含原理对象、验收准则、约束）。
- 过程：系统工程工具将需求约束映射到功能/逻辑/物理模型，生成多个方案分支。
- 输出：ABOM 方案树，每个节点保留原理对象引用、参数初值和评审信息。

### 4.2 ABOM → DBOM
- 输入：评审后选定方案（ABOM 节点状态 = 选定）。
- 过程：细化功能/逻辑模型为可制造的设计实体，补齐图纸、MBD、材料、接口。
- 输出：DBOM 设计树，作为跨域数据骨架，并继承原理对象引用。

### 4.3 DBOM → CAEBOM/TBOM
- 输入：DBOM 结构与零部件属性。
- 过程：
  - 仿真侧按零部件类型和模板生成仿真类型→实例→版本结构。
  - 试验侧按零部件/组合件生成试验类型→项目→任务结构。
- 输出：CAEBOM/TBOM，保留 DBOM 路径并继承原理对象。

## 5. 详细示例：XX 型号发动机
### 5.1 RBOM 结构（节选）
```
- XX 型号发动机需求 [原理对象: PO-ENG-ROOT]
  - 系统级需求
    - 发动机一般要求 [PO-ENG-GEN]
    - 功能要求 [PO-ENG-FUNC]
      - 点火方式 [PO-ENG-IGN]
      - 比冲 [PO-ENG-ISP]
      - 最大推力 [PO-ENG-TMAX]
  - 系统架构需求
    - 架构模型 [PO-ARCH-SYS]
  - 系统结构需求
    - 骨架模型 [PO-STRUCT-SYS]
  - XX 推力室需求
    - 组件级需求 [PO-TC-FUNC]
      - 性能要求 [PO-TC-PERF]
      - 功能要求 [PO-TC-FUNC]
    - 架构需求 [PO-TC-ARCH]
      - 架构模型 [PO-TC-ARCH]
    - 结构需求 [PO-TC-STRUCT]
      - 骨架模型 [PO-TC-STRUCT]
  - YY 涡轮泵需求
    - 组件级需求 [PO-TP-FUNC]
      - 性能要求 [PO-TP-PERF]
      - 功能要求 [PO-TP-FUNC]
    - 架构需求 [PO-TP-ARCH]
    - 结构需求 [PO-TP-STRUCT]
```

### 5.2 原理对象映射示意
| 原理对象 | 描述 | 需求节点 | 方案节点 | 设计节点 |
| --- | --- | --- | --- | --- |
| PO-TP-COAX | 同轴涡轮泵双级增压原理 | YY 涡轮泵需求/功能要求 | 发动机方案三/同轴涡轮泵 | 同轴涡轮泵组件（泵、涡轮、转子） |
| PO-IGN-HOT | 热点火原理 | 点火方式 | 方案共性配置 | 点火子系统 |
| PO-TC-REGEN | 推力室再生冷却原理 | XX 推力室需求/性能要求 | 方案热管理设计 | 推力室身部/冷却通道 |
| PO-PRE-DBL | 双预压泵原理 | 系统级功能要求 | 发动机方案三/双预压泵 | 双预压泵组件 |

### 5.3 ABOM 方案结构
```
- XX 型号方案
  - 发动机方案一（同轴涡轮泵） [PO-TP-COAX]
    - 同轴涡轮泵
      - 功能架构模型
      - 逻辑架构模型
      - 物理架构模型（初步）
      - 参数
      - 相关文件
    - 推力室
  - 发动机方案二（双涡轮泵） [PO-TP-DUAL]
    - 双涡轮泵
    - 推力室
  - 发动机方案三（同轴涡轮泵 + 双预压泵）
    - 同轴涡轮泵 [PO-TP-COAX]
    - 同轴涡轮泵（冗余评估） [PO-TP-COAX]
      - 功能架构模型
      - 逻辑架构模型
      - 物理架构模型（初步）
    - 双预压泵 [PO-PRE-DBL]
    - 推力室 [PO-TC-REGEN]
```
- 方案评审：方案三达成性能指标且风险可控，被标记为“选定”，其余方案标记为“备选/废弃”。

### 5.4 ABOM → DBOM 转化
- 系统自动复制方案三节点，生成 DBOM 根：`XX 型号方案三`。
- 原理对象引用继承：如同轴涡轮泵节点继续引用 `PO-TP-COAX`。
- 补充设计属性（材料、工艺、图纸、接口），如下所示。

### 5.5 DBOM 结构（节选）
```
- XX 型号方案三
  - 同轴涡轮泵 [PO-TP-COAX]
    - 涡轮
    - 泵
      - 物理架构模型
      - 叶片型面模型
      - MBD 属性
      - 三维模型
      - 工程图纸
      - 设计文件
      - 质量特性
      - 原理图/安装图
    - 转子
    - 密封
  - 双预压泵 [PO-PRE-DBL]
  - 燃烧室 [PO-TC-REGEN]
    - 身部
    - 头部
  - 推力室 [PO-TC-REGEN]
```

### 5.6 DBOM → CAEBOM/TBOM
**CAEBOM（仿真侧）示例**
```
- 同轴涡轮泵 [继承 PO-TP-COAX]
  - 仿真类型：结构强度
    - 实例：ST-TP-001
      - 版本：v1（初始）
      - 版本：v2（更新叶片型面）
  - 仿真类型：热-流耦合
    - 实例：CFD-TP-003
      - 版本：v1（设计基线）
```
**TBOM（试验侧）示例**
```
- 同轴涡轮泵 [继承 PO-TP-COAX]
  - 试验类型：性能标定
    - 项目：TP-TST-001
      - 任务：满功率工况
      - 任务：部分负荷工况
  - 试验类型：耐久试验
    - 项目：TP-DUR-002
      - 任务：500 小时台架试验
```
- 仿真/试验节点自动继承原理对象 ID，输出的分析/试验报告在 `evidenceRefs` 中关联回原理对象，实现证据闭环。

## 6. 数据治理与工具支撑
- **统一编号体系**：`xbomNodeId`（结构节点）、`principleId`（原理对象）、`baselineId`（基线）、`changeId`（变更）统一管理。
- **版本与基线控制**：RBOM/ABOM/DBOM 共享基线号；CAEBOM/TBOM 记录来源基线与仿真/试验版本号。
- **工具集成**：
  - 需求管理工具（RBOM）↔ 系统工程工具（ABOM）通过原理对象 ID 同步。
  - PLM 平台承载 DBOM 与 CAEBOM/TBOM，提供映射校验与影响分析。
  - 仿真/试验平台回写结果至 PLM，并挂接原理对象。
- **自动校验**：新增节点或变更时，检查原理对象映射是否完整；缺失时阻断发布并提示处理流程。

## 7. 风险点与控制措施
| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 原理对象粒度过粗 | 映射模糊，难以定位验证对象 | 制定拆分指南，按照单一功能/约束划分；设立评审机制 |
| 原理对象粒度过细 | 退化为物理件级，跨阶段失联 | 定义功能-原理-实现分层模型，禁止直接等同零件 |
| 方案淘汰未清理映射 | 旧方案残留影响统计与追溯 | 设置状态字段（候选/选定/废弃），定期清理并记录历史 |
| 转化过程中遗漏原理对象 | 出现悬挂节点，审计失败 | 在工具链中实施强制校验与审批流程 |
| 变更未同步下游 | 仿真/试验使用过期设计 | ECO 触发自动影响分析，标记需重算/重试节点 |

## 8. 落地步骤建议
1. **建立原理对象词典**：梳理现有 RBOM，提炼核心原理对象并补齐字段。
2. **构建映射模板**：在系统工程工具与 PLM 中配置“需求→原理→方案→设计→仿真/试验”的映射模板。
3. **试点运行**：选取“同轴涡轮泵”子系统跑通全流程，验证映射、变更与证据闭环。
4. **完善自动校验**：上线新增/变更时的原理对象校验、影响分析与状态提醒。
5. **扩展度量与看板**：基于原理对象聚合覆盖率、成熟度、剩余风险，支撑总师与主任工程师决策。
